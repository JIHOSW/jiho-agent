## A. 기술: Amazon Bedrock

### [A1] Amazon Bedrock 서울·싱가포르 리전 내 추론 발표

- 기관/문서명: AWS Machine Learning Blog, "Introducing Anthropic models on Amazon Bedrock for in-region inference in Seoul and Singapore"
- URL: https://aws.amazon.com/blogs/machine-learning/introducing-anthropic-models-on-amazon-bedrock-for-in-region-inference-in-seoul-and-singapore/
- 발행일: 2026-09-29 (AWS 페이지 표기 기준. 일부 재게시 사이트는 9월 30일로 표기)
- 상태: 확인됨 (페이지 끝부분 일부 잘림)
- 핵심 내용:
  - 서울(ap-northeast-2)에서 Claude Opus 5, Claude Sonnet 5를 리전 내 추론으로 쓸 수 있음. 싱가포르는 Sonnet 5만.
  - bedrock-runtime 엔드포인트, 직접 모델 ID로 호출. 교차 리전 추론과 달리 라우팅 계층이 없고, 요청이 호출한 리전 안에서만 처리된다고 설명.
  - 처리량은 해당 리전 용량과 리전별 할당량에 묶임. 요금은 호출 리전의 온디맨드 표준 요금.
  - CloudWatch 지표, CloudTrail 로그도 같은 리전 범위.
  - 한국·싱가포르의 금융, 의료, 공공 분야 데이터 처리 요건을 배경으로 언급. 특정 법령이나 인증 이름은 없음.
- 글에서 쓸 곳: "무엇이 새로 가능해졌나" 도입부 사실
- 주의: 데이터 보관(retention) 위치는 이 글에 없음 → [A5]로 보완. Knowledge Bases, 배치, 에이전트 적용 여부는 이 글에서 다루지 않음.

### [A2] Claude Sonnet 5 모델 카드 (리전별 추론 옵션표)

- 기관/문서명: Amazon Bedrock User Guide, "Claude Sonnet 5"
- URL: https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-5.html
- 발행일: 표기 없음 (모델 출시일 2026-06-30)
- 상태: 확인됨
- 핵심 내용:
  - bedrock-runtime 기준 서울 행: In-Region 지원, Geo(지역 단위 교차 리전) 미지원, Global 지원.
  - 지역 단위(Geo) 프로필은 us, eu, au, in만 있음. 즉 서울에서 쓸 수 있는 선택지는 "서울 단일 리전" 또는 "전 세계 라우팅" 두 가지.
  - 도쿄, 오사카는 Global만 지원.
- 글에서 쓸 곳: "선택지가 둘로 갈린다"는 설명, 도입 전 확인 항목
- 주의: 모델마다, 시점마다 표가 바뀜. Opus 5 모델 카드는 따로 확인하지 않음 (`확인필요_목록.md` 참조).

### [A3] 교차 리전 추론(Cross-Region Inference) 개요

- 기관/문서명: Amazon Bedrock User Guide, "Route model inference requests across AWS Regions with cross-Region inference"
- URL: https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html
- 상태: 확인됨
- 핵심 내용:
  - 지역 단위(Geographic) 프로필은 지정 지역 안에서, 전역(Global) 프로필은 전 세계 상용 리전에서 처리.
  - AWS는 데이터 상주 요건이 있으면 지역 단위를, 비용 절감이 우선이면 전역(약 10% 저렴)을 권장.
  - 리전 간 전송은 AWS 네트워크 안에서 암호화되어 이동.
  - CloudTrail은 요청을 보낸 리전에 기록하고, `additionalEventData.inferenceRegion` 필드로 실제 처리 리전을 확인할 수 있음.
- 글에서 쓸 곳: "어디서 처리됐는지 증명하는 방법" (도입 전 확인 항목)

### [A4] 지역 단위 교차 리전 추론 세부

- 기관/문서명: Amazon Bedrock User Guide, "Geographic cross-Region inference"
- URL: https://docs.aws.amazon.com/bedrock/latest/userguide/geographic-cross-region-inference.html
- 상태: 확인됨
- 핵심 내용:
  - 교차 리전 추론에서는 입력과 출력이 호출 리전 밖으로 이동할 수 있음. 오남용 탐지용으로 저장할 때는 처리된 목적지 리전에 저장.
  - SCP(조직 단위 서비스 제어 정책)로 리전을 막아 두면 목적지 리전이 막힌 경우 요청이 실패함.
- 글에서 쓸 곳: 리전 내 추론과 교차 리전 추론의 차이 설명
- 관련: 추론 프로필 지원 페이지(https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)는 데이터 상주 요건이 있으면 쓰려는 모든 원본 리전에서 GetInferenceProfile로 목적지 리전을 직접 확인하라고 안내함. 프로필 ID의 접두어만 믿지 말라는 취지.

### [A5] 데이터 보관(Data retention) 설정

- 기관/문서명: Amazon Bedrock User Guide, "Data retention"
- URL: https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html
- 상태: 확인됨
- 핵심 내용:
  - 프롬프트와 출력의 보관 여부를 리전별로 계정 또는 프로젝트 단위에서 설정. 다른 리전에는 전파되지 않음.
  - 모드: none(무보관), default(모델 기본 정책), aws_review(AWS가 보관하고 사람 검토 가능), provider_data_share(레거시).
  - Claude Fable 5, 5.1은 aws_review 이상이 필요. 해당 모델의 입력과 출력은 AWS 경계 안에서 최대 30일 보관되고 모델 제공사와는 공유되지 않는다고 설명.
  - 교차 리전 추론을 쓰면 보관 데이터는 목적지 리전에 저장.
  - SCP로 조직 전체에 무보관(none)을 강제할 수 있음.
- 글에서 쓸 곳: 처리 위치와 보관 정책은 별개의 질문이라는 점
- 주의: 리전 내 추론으로 쓰는 Sonnet 5, Opus 5에 기본으로 적용되는 보관 모드는 모델 카드에서 확인하지 못함 → `확인필요_목록.md`

### [A6] 오남용 탐지(Abuse detection)

- 기관/문서명: Amazon Bedrock User Guide, "Amazon Bedrock abuse detection"
- URL: https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html
- 상태: 확인됨
- 핵심 내용: 일부 모델(OpenAI 일부, Claude Fable 5, 5.1)은 오남용 탐지 목적으로 입력과 출력을 최대 30일 보관. 보관 데이터는 AWS가 처리하며 모델 제공사와 공유하지 않음. 교차 리전 추론이면 목적지 리전에 저장.
- 글에서 쓸 곳: 보관 정책은 모델마다 다르므로 모델별로 확인해야 한다는 점

### [A7] 데이터 보호, 모델 배포 계정

- 기관/문서명: Amazon Bedrock User Guide, "Data protection"
- URL: https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html
- 상태: 확인됨
- 핵심 내용: 공동 책임 모델이 적용됨. 리전마다 모델 제공사별 배포 계정을 Bedrock 팀이 소유·운영하며, 모델 제공사는 이 계정, 로그, 고객 프롬프트에 접근하지 못한다고 설명.
- 글에서 쓸 곳: "모델 회사가 우리 데이터를 보나"라는 질문에 답하는 근거
- 주의: 공동 책임 모델이므로 고객 측 설정(IAM, 로깅, 보관 모드)은 고객 책임. 이 점을 함께 씀.

### [A8] 정형 데이터 Knowledge Bases의 교차 리전 추론

- 기관/문서명: Amazon Bedrock User Guide, "Cross-region inference for knowledge bases with structured data store"
- URL: https://docs.aws.amazon.com/bedrock/latest/userguide/kb-structured-cris.html
- 상태: 확인됨
- 핵심 내용: 2026-05-10부터 정형 데이터 저장소를 쓰는 Knowledge Bases(GenerateQuery, Retrieve, RetrieveAndGenerate)는 교차 리전 추론을 자동으로 사용. 서울은 지역 단위 교차 리전 추론이 없어 추론 요청이 지역 밖에서 처리될 수 있다고 명시. 별도 설정 없이 자동 적용.
- 글에서 쓸 곳: **핵심 반례.** 모델 호출이 서울 리전 내 추론이어도 같이 쓰는 기능에 따라 처리 위치가 달라질 수 있음 → "기능별로 처리 위치를 확인하라"는 도입 전 확인 항목의 근거

- 발행일: 2026-04-20 (금융안전과)
- 상태: 확인됨
- 핵심 내용:
  - 「전자금융감독규정시행세칙」 개정으로 2026-04-20부터 내부 업무망의 SaaS 이용에 망분리 예외 적용. 별도 혁신금융서비스 심사가 필요 없음.
  - 이용자의 고유식별정보, 개인신용정보를 처리하면 예외 불가. 가명정보는 기존처럼 혁신금융서비스 지정이 필요.
  - 조건: 침해사고 대응기관(금융보안원 등) 평가를 받은 SaaS, 단말 보호대책, 반기 1회 통제 이행 평가와 정보보호위원회 보고.
  - 생성형 AI 서비스도 망분리 예외 적용을 신속히 추진할 계획이라고 밝힘.
- 글에서 쓸 곳: 금융 고객의 질문이 "데이터 위치"에서 "어떤 정보를 넣을 수 있나"로 옮겨 가는 근거
- 주의: Bedrock API 호출이 이 시행세칙의 "SaaS"에 해당하는지는 원문에서 확인하지 못함 → `확인필요_목록.md`

### [A10] Amazon Quick Smart Approvals 사용자 가이드
- 기관/문서명: Amazon Quick User Guide, "Smart Approvals"
- URL: https://docs.aws.amazon.com/quick/latest/userguide/smart-approvals.html
- 상태: 확인됨
- 핵심 내용:
  - 판단 순서: ① 기존 통제(권한, 가드레일, 커넥터 작업 권한, 사용자 설정)를 먼저 적용하고, 정책상 사람 승인이 필요한 작업은 항상 사람에게 감 ② 자동 검토 대상 중 요청과 맞고 위험이 낮은 작업만 자동 승인 ③ 외부 전송, 권한 변경, 삭제·덮어쓰기, 결제는 사람에게 넘김. 검토 실패나 시간 초과도 사람에게 넘김.
  - 자동 검토 대상은 커넥터가 "사용자 선택"이고 사용자가 "매번 묻기"로 설정한 작업뿐. "항상 허용"은 검토 없이 실행됨.
  - 문서 스스로 자동 검토가 정책을 대신하지 않는다고 밝힘. 반드시 사람이 승인해야 하는 작업은 커넥터 작업 권한으로 고정하라고 권함.
  - 기본으로 켜져 있음. 관리자가 권한 프로필로 끌 수 있음. 데스크톱·모바일 앱에서만 제공.
  - CloudTrail에 자동 승인 기록(approvalSource = SMART_APPROVALS)과 설정 변경이 남음. 다만 승인 기록이 실제 실행을 뜻하지는 않음.
- 글에서 쓸 곳: 도입부 사례, "자동 승인은 정책 다음 단계"라는 구조 설명
