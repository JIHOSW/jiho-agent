# 동향 요약 체크리스트

> 버전: 1.0  
> 사용 시점: 동향 요약 초안 완성 직후 (에이전트가 자동 점검) / 발행 전 (사람)  
> 판정: 통과 / 수정 필요  
> "필수" 항목이 하나라도 통과하지 못하면 완료로 처리하지 않는다.

## 1. 필수: 사실과 출처

- [ ] 항목마다 기관, 발표 제목, 발표일, URL이 있다.
- [ ] 출처는 1차 자료(기업 공식 블로그·문서, 정부·감독기관 보도자료)다. 기사는 단서로만 쓴다.
- [ ] 출처를 실제로 열어 내용을 확인했다.
- [ ] 발표일이 수집 기간 안에 있다. (기본: 직전 7일)
- [ ] 전망·계획과 확정·출시를 구분했다. ("~할 계획", "프리뷰", "정식 출시")
- [ ] 원문으로 확인하지 못한 내용은 `[확인 필요: X번호]`로 표시하고, `03_동향/날짜/출처.md`에 같은 번호로 적었다.

## 2. 필수: 표현과 위험

- [ ] 항목마다 "무슨 일인지"(사실)와 "금융 고객에게 의미"(해석)가 문장으로 나뉘어 있다.
- [ ] 해석 문장은 한 줄이고, 해석 표지(`제가 보기에`, `~라고 볼 수 있습니다`)가 있다.
- [ ] 규제 충족을 보장하거나 법률 자문처럼 단정하는 문장이 없다.
- [ ] 솔트웨어의 공식 입장처럼 쓰지 않았고, 경쟁사를 비방하지 않았다.
- [ ] 원문 문장을 그대로 옮기지 않았다.
- [ ] 글 끝에 고지 문구가 있다.

## 3. 구조와 표기

- [ ] 항목은 3~5개, 전체 1,000~1,500자다.
- [ ] 첫 문단에 이번 주 핵심 한 줄이 있다.
- [ ] 분석 글 후보 표시가 0~1개 있다. (없으면 "없음")
- [ ] 합쇼체, 금지 표현(`?`, `!`, `여러분`, AI투) 규칙을 지켰다.
- [ ] 회사명, 제품명이 공식 표기와 같다.
- [ ] 출처는 목록 형식이다.
