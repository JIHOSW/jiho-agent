# 검수 체크리스트

> 버전: 1.3 (분석 글용. 동향 요약은 `동향_체크리스트.md`)  
> 사용 시점: 초안 검수(초안 완성 직후) / 발행 전 검수(사람 검토와 수정 후)  
> 판정: 통과 / 수정 필요 / 확인 필요  
> 하나라도 "필수" 항목이 통과하지 못하면 완료로 처리하지 않는다.  
> `(발행 전)` 표시 항목은 발행 전 검수에서만 엄격히 적용한다. 초안 검수에서는 각 항목에 적힌 초안 기준을 적용한다.

## 1. 필수: 사실과 출처

- [ ] 핵심 수치와 주장에 기관, 문서명, 날짜, URL이 있다.
- [ ] 출처를 실제로 열어 내용이 일치하는지 확인했다.
- [ ] 출처 번호가 붙은 문장마다, 그 번호의 원문 페이지에 해당 내용이 있다. 검색 결과 요약에서만 본 내용에 다른 페이지의 출처 번호를 달지 않았다.
- [ ] 수치의 조사 대상, 표본, 기준일을 확인했다.
- [ ] 전망치와 확정치를 구분했다.
- [ ] 법령과 규정의 이름, 조항, 시행일을 원문으로 확인했다.
- [ ] 회사 수치와 파트너 정보는 작성 시점의 공식 자료와 일치한다.
- [ ] 공개 자료로 확인되지 않은 내용이 없다.
- [ ] (발행 전) `[확인 필요]` 표시가 남아 있지 않다.
  - 초안 기준: 남은 표시가 모두 `[확인 필요: X번호]` 형식이고, 그 번호가 `04_출처/확인필요_목록.md`에 있으면 통과.
- [ ] (발행 전) 출처 없는 일반 정의 문장(예: 망분리, SaaS)을 사람이 확인했다.

## 2. 필수: 표현과 위험

- [ ] 사실, 해석, 제안이 구분되어 있다.
- [ ] 출처 없는 인과 설명이나 일반화 문장에 해석 표지(`제가 보기에`, `~라고 볼 수 있습니다`)가 있다.
- [ ] 규제 충족이나 감사 통과를 보장하는 표현이 없다.
- [ ] 법률 자문처럼 단정한 문장이 없다.
- [ ] 특정 금융사의 내부 사정을 추측하지 않았다.
- [ ] 가상 사례임을 밝혔다.
- [ ] 솔트웨어의 공식 입장처럼 쓰지 않았다.
- [ ] 경쟁사를 비방하지 않았다.
- [ ] 원문 문장이나 구성을 그대로 따라 쓰지 않았다.
- [ ] 글 끝에 고지 문구가 있다.

## 3. 구조

- [ ] 첫 3문장 안에 결론이 있다.
- [ ] 금융 고객의 질문 1개가 명확하다.
- [ ] 고객 영향이 업무, 보안, 규제, 비용 중 하나 이상으로 설명된다.
- [ ] 도입 전 확인할 항목이 있다.
- [ ] 지금 검토할 경우와 기다릴 경우가 나뉘어 있다.
- [ ] (발행 전) `내 관점`을 작성자가 작성하고 확인했다.
  - 초안 기준: `<!-- 내 관점: 작성자 -->` 주석 자리 표시가 있으면 통과.

## 4. 표기

- [ ] 회사명, 제품명, 파트너명이 공식 표기와 일치한다.
- [ ] 전문용어의 철자가 맞고 처음 나올 때 설명했다. (`style-guide.md` 10절의 용어 목록 포함)
- [ ] `[입력]`, `TODO`, `기자 참고`, 상태 메타 줄 같은 내부 문구가 없다. (`<!-- -->` 주석은 화면에 보이지 않으므로 초안 검수에서 허용)
- [ ] 제목, 본문, 표, 이미지의 명칭과 수치가 일치한다.
- [ ] 문체와 금지 표현 규칙을 지켰다. 소제목은 명사형 또는 `~다`, 15자 이내.
- [ ] 표가 모바일에서 읽힌다. 열은 3개 이하로 하고, 출처는 표가 아니라 목록으로 쓴다.
