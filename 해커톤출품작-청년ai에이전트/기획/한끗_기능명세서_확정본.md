## REQ-001 일자리 조건 입력과 정보 확인
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

청년 사용자가 공고 사진(스크린샷 포함), 공고·제안 메시지 붙여넣기 또는 직접 입력으로 근무 조건을 제출하고 추출한 값을 확인하는 영역이다. 직접 입력에는 시급, 주당 근무시간, 요일, 시작일과 종료일 또는 기간, 지급 방식을 포함하며 소득 종류 후보는 근로소득·일용근로소득·사업소득(3.3%)·모름으로 확인한다. 가상 샘플 세 개로 같은 입력 흐름을 체험할 수 있고, 사진 판독 실패는 추출 확인 안에서 직접 입력으로 전환한다. 공고 링크, PDF·Word 파일, 일자리 검색 및 계약 체결은 포함하지 않는다.

**수용 기준:**
```
1. ✓ 사용자가 사진을 올리거나 공고·메시지를 붙여넣으면 원문 발췌와 시급·근무시간·기간·소득 종류 후보를 확인하고 항목별 확정·추정·확인 필요 상태를 볼 수 있다.
2. ✓ 사용자가 직접 입력하거나 추출값을 수정한 뒤 계산에 사용할 조건을 확정할 수 있다.
3. ✓ 사용자가 주말 카페 알바 공고, 3.3% 떼는 제안 메시지, 지급 방식이 없는 공고의 가상 샘플 세 개 중 하나를 불러와 바로 시연할 수 있다.
4. ✓ 사진에서 조건을 읽지 못하면 사용자는 추출 확인 화면에서 안내와 직접 입력 전환 버튼을 보고, 필수 조건이 모호하면 추가 질문을 거쳐야 다음 단계로 갈 수 있다.
```

## REQ-002 개인 및 제도 수급 조건 확인
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

청년 사용자의 만 나이, 구직촉진수당 수급 여부(예·아니오·신청 중), 부모의 건강보험 피부양자 및 연말정산 부양가족 여부(예·아니오·모름), 올해 이미 번 소득의 종류별 금액, 부모의 연 소득 구간, 그 밖의 지원을 확인하는 영역이다. 부족한 정보가 미치는 제도를 입력 항목 곁에 알리고 일자리 조건과 함께 요약한다. 가구 합산 연소득, 부모와 동거 여부, 피부양자 연간 소득 기준 초과 여부, 월 평균 근무 시간은 입력하지 않으며 자격 신청과 신고를 대행하지 않는다.

**수용 기준:**
```
1. ○ 사용자가 내 상황을 입력하면 화면은 지정된 항목만 제시하고 예·아니오·신청 중·모름 등의 상태를 항목에 맞는 선택지 버튼으로 제공한다.
2. ○ 정보가 부족하면 사용자는 해당 입력 옆에서 어느 제도가 범위로만 표시되는지 확인할 수 있고, 신청 중인 구직촉진수당은 확정 수급으로 계산되지 않는다.
3. ○ 사용자가 입력 요약을 확인하면 각 값이 사용되는 제도를 알 수 있고 일자리 조건 또는 내 상황의 해당 값을 수정할 수 있다.
4. ○ 사용자가 규칙표에 없는 지원을 선택하면 그 지원은 계산되지 않고 확인 필요 안내와 문의처를 확인할 수 있다.
```

## REQ-003 공식 규칙 기반 기준선과 금액 계산
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

검증된 규칙표를 코드가 참조해 부모 연말정산 부양가족 공제, 건강보험 피부양자, 구직촉진수당, 주 15시간 기준에 따른 주휴수당·4대보험의 영향과 기준선 초과 시점·실질 순소득을 계산하는 영역이다. 규칙마다 기대값 테스트를 두고 인공지능은 판정·금액 계산을 변경하지 않는다. 근로장려금·실업급여·훈련장려금은 원문 확인 후 추가할 확대 후보이며 규칙표에 없으면 계산하지 않고 확인 필요 안내만 한다.

**수용 기준:**
```
1. ○ 사용자가 필수 조건을 확정하면 네 가지 계산 대상 각각에서 적용 가능한 기준선 초과 여부, 예상 시점과 손익을 확인할 수 있다.
2. ○ 계산 가능한 사례에서 사용자는 추가 소득, 줄어드는 수당과 늘어나는 부담을 반영한 실질 순소득을 확인할 수 있다.
3. ○ 규칙표의 각 규칙에는 기대값 테스트가 있고 검증 시 모두 통과한다.
4. ○ 공식 원문이 확인되지 않은 규칙이나 규칙표에 없는 제도를 요청하면 사용자는 확정 계산 대신 확인 필요 상태와 문의처를 확인한다.
```

## REQ-004 근무 조건 대안 비교와 추천
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

청년 사용자가 원래 근무 조건과 기준선을 넘지 않는 최대 근무시간, 기준선을 넘더라도 총수입이 증가하는 조건을 비교하는 영역이다. 인공지능 에이전트가 규칙 계산을 반복 호출해 근무 조건을 바꿔 가며 대안을 찾고, 선택한 대안의 월별 영향과 고용주에게 보낼 근무시간 조정 요청 문구를 제공한다. 실제 채용 공고 검색이나 고용주와의 협상 대행은 포함하지 않는다.

**수용 기준:**
```
1. ○ 계산 가능한 조건에서 사용자는 원래 조건과 기준선을 넘지 않는 최대 근무시간, 넘더라도 총수입이 증가하는 조건의 근무시간·추가 소득·지원 변화·순소득·넘는 기준선을 비교한다.
2. ○ 검토자는 대안이 인공지능 에이전트의 규칙 계산 반복 호출과 조건 변경으로 도출되고, 사용자는 어떤 조건을 바꿨는지 확인할 수 있다.
3. ○ 사용자가 대안을 선택하면 해당 대안의 월별 변화와 고용주에게 보낼 근무시간 조정 요청 문구를 보고 복사할 수 있다.
4. ○ 필수 정보가 부족하면 사용자는 생성되지 않은 대안 대신 부족한 정보와 공식 확인 안내를 본다.
```

## REQ-005 근거와 규칙 버전 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

정부·공공기관 원문에 검증된 규칙표를 코드와 분리된 데이터 파일로 유지하고 규칙마다 근거 조문, 적용 연도, 확인일, 상태 및 해당 산정 조건을 다루는 영역이다. 현행 규칙을 기본 계산에 사용하고 개정 중인 기준은 결과 카드에서 현행과 개정안을 나란히 구분한다. 관리자용 규칙 관리·등록 화면은 제공하지 않으며 원문 확인이 끝난 제도만 규칙표에 추가한다.

**수용 기준:**
```
1. ○ 결과를 보는 사용자는 제도별 원문 링크, 근거 조문, 적용 연도, 확인일과 규칙 상태를 확인할 수 있다.
2. ○ 현행과 개정안이 함께 있으면 사용자는 카드에서 두 기준의 결과를 나란히 보되 현행 기준의 계산 결과가 기본임을 알 수 있다.
3. ○ 검토자는 규칙표가 코드와 분리된 데이터 파일이며 규칙마다 근거 조문·적용 연도·확인일·상태를 가지고 있음을 확인할 수 있다.
4. ○ 공식 원문 확인 전의 제도 또는 검증되지 않은 규칙은 계산에 쓰이지 않고 사용자는 확인 필요 안내를 본다.
```

## REQ-006 결과 설명과 다음 행동 안내
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

청년 사용자가 결과 카드와 월별 누적 소득을 보며 네 가지 계산 제도 각각의 기준선, 예상 초과 시점, 손익과 확정·추정·확인 필요 상태를 이해하도록 하는 영역이다. 로딩·계산 보류·지원 범위 외는 결과 화면의 상태로 표시하고, 근거 조문·확인일·신고 의무·공식 문의처는 근거와 다음 행동 화면에 모아 보여준다. 여유가 있으면 내 기록 화면에서 올해 월별 소득과 이전 결과를 브라우저 안에서만 다루며, 행정기관의 최종 판단을 대체하지 않는다.

**수용 기준:**
```
1. ○ 사용자는 결과 화면에서 계산 중 상태, 네 가지 제도 카드, 월별 누적 소득 타임라인과 순소득 요약을 확인할 수 있다.
2. ○ 사용자는 보류된 제도의 사유와 다음 행동 및 범위 밖 제도의 비계산 안내와 문의처를 별도 안내 화면 없이 카드에서 확인할 수 있다.
3. ○ 사용자는 근거와 다음 행동 화면에서 계산에 쓴 조건, 부족한 정보, 원문·적용 연도·확인일, 신고 의무와 공식 문의처를 확인한다.
4. ○ 결과를 보여주는 영역의 하단에는 참고용 계산 및 인공지능 생성 내용에 관한 두 고지가 표시된다.
```

## REQ-007 품질 검증
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중

가상 사례 평가 세트로 사진·문장의 근무 조건 추출과 소득 종류 판별의 정확도를 측정하고 기록하는 영역이다. 실제 제도 기준선의 값을 임의로 정하거나 검증되지 않은 규칙을 도입하는 일은 포함하지 않는다.

**수용 기준:**
```
1. ○ 검토자가 가상 사례 평가 세트를 실행하면 조건 추출 결과와 기대값의 일치 여부를 확인할 수 있다.
2. ○ 검토자가 소득 종류 판별을 평가하면 근로소득·일용근로소득·사업소득·모름 각각의 판별 결과와 기대값의 차이를 확인할 수 있다.
3. ○ 검토자는 실행한 평가의 정확도와 결과 기록을 다시 확인할 수 있다.
```

## REQ-008 인공지능 호출 장애 대응
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

사용자가 조건 추출이나 질문·대안 생성을 기다릴 때 인공지능 호출 실패 또는 사용 한도를 만나도 흐름을 이어갈 수 있도록 안내하는 영역이다. 재시도 안내와 가상 샘플 결과 보기만 다루며, 실패한 호출을 성공한 계산으로 꾸미거나 확정 결과로 제시하지 않는다.

**수용 기준:**
```
1. ○ 인공지능 호출이 실패하면 사용자는 실패 상태와 재시도 안내를 볼 수 있다.
2. ○ 인공지능 호출 한도에 걸리면 사용자는 한도 상태와 가상 샘플 결과 보기 경로를 볼 수 있다.
3. ○ 사용자가 샘플 결과를 보면 실제 본인의 확정 계산과 구분된 가상 사례임을 알 수 있다.
```

## 프로덕트 정책

### POL-001 입력값 보관 원칙

적용 대상: - 일자리 조건, 개인·수급 조건, 월별 소득 기록과 이전 계산 결과에 적용한다.

저장 장소:
  - 개인정보는 서버에 저장하지 않는다.
  - 입력값과 내 기록은 사용자의 브라우저 안에서만 유지한다.

사용자 안내:
  - 사진 입력 화면은 실제 개인정보가 담긴 사진을 올리지 말라고 안내한다.
  - 내 기록 화면은 기록이 브라우저에만 저장된다고 안내한다.

계정 없이 사용하는 서비스의 입력값 보관 범위를 정한다.

### POL-002 신고 회피 안내 금지

적용 범위: - 결과 설명, 대안 비교와 요청 문구에 적용한다.

금지 안내: - 서비스는 소득을 숨기거나 신고를 피하는 방법을 안내하지 않는다.

결과 고지:
  - 결과 영역 하단에는 "참고용 계산이며 세무·법률 자문과 행정기관의 최종 판단을 대체하지 않습니다"를 표시한다.
  - 결과 영역 하단에는 "AI가 생성한 내용이 포함되어 있습니다"를 표시한다.

계산 결과와 근무 조건 제안의 안내 범위를 정한다.
