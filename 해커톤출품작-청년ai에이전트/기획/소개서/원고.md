## 02 대상 사용자

- 핵심 문장: 일하면서 정부 지원을 받는 청년과 부모님 보험·공제에 걸린 청년
- 주요 사용자(Primary): 일을 시작하거나 늘리려는 청년 중
  1. 구직촉진수당(국민취업지원제도)을 받는 청년: "이 일을 하면 수당이 얼마나 줄지?" (예시: 27세, 수당 6월까지, 주말 카페 주 24시간 제안)
  2. 부모님 건강보험 피부양자·연말정산 부양가족인 대학생: "부모님 보험·세금에 영향이 있을지?" (예시: 20세, 3.3% 떼는 학원 보조 주 12시간)
  3. 조건이 빠진 공고를 받은 청년: "무엇을 물어봐야 할지?" (예시: 23세, 지급 방식이 없는 편의점 공고)
  - 예시는 앱의 가상 예시(`munteok/js/samples.js`)
- 보조 사용자·이해관계자
  - 부모님: 피부양자 자격과 연말정산 부양가족 공제에 영향을 받음 → 결과를 함께 보고 정부24·건강보험공단에서 확인
  - 고용주(사장님): 근무시간·지급 방식·주휴수당 확인 질문을 시작 전에 받음
  - 고용센터·건강보험공단·국세청: 청년이 신고할 것과 물어볼 것을 정리해 문의(1350·1577-1000·126)
- 사용자가 얻는 가치
  - 일하기 전에 '남는 돈'(번 돈 − 보험료·세금 − 줄어드는 정부 지원)을 달마다 앎
  - 근무시간을 바꾸면 무엇이 달라지는지 보고 직접 고름(추천 순위가 아니라 비교 기준)
  - 사장님께 보낼 확인 문구와 신고할 곳·시점 체크리스트
  - 로그인 없이 바로, 입력은 한끗 서버에 저장하지 않음

## 03 AI를 활용한 해결 방안

- 핵심 문장: AI는 공고를 읽고, 계산은 공식 기준표가 해요
- 해결 방안 개요: 공고 사진·글 → AI가 조건 5개 + 원문 근거 + 확인 수준 → 확실하지 않은 것만 되묻기 → 규칙 엔진이 4개 제도 계산 → 남는 돈·근무시간 비교·문구·시작 전 준비
- 왜 AI여야 하는가
  1. 공고 표기가 제각각: 시급·월급·일당·3.3%, 요일·시간대·휴게시간, 캡처 사진 → 정해진 규칙으로는 다 못 읽음
  2. 읽으면서 계산·해석이 필요: "금·토·일 10:00~19:00(휴게 1시간)" → 하루 8시간 × 3일 = 주 24시간
  3. 소득 종류는 단서로 판별: "3.3% 떼고" → 사업소득, "4대보험 가입" → 근로소득. 이 판별이 어떤 제도가 적용되는지를 가름
  - 반대로 금액·기준선 판정은 틀리면 안 되므로 AI에 맡기지 않음
- AI 적용 지점 (`munteok/api/extract.js`)
  1. 조건 읽기: 사진(최대 3장, 긴 변 1,600px로 줄여 보냄)·글(4,000자까지)에서 시급, 주당 근무시간, 시작 월, 기간, 소득 종류
  2. 근거와 확인 수준: 항목마다 원문 구절 + 확정·추정·확인 필요 → 화면이 원문에 형광펜, 추정·빈칸만 하나씩 되묻기
  3. 공고 판별: 일자리 공고·제안이 아니면 거절
  4. 형식 고정: 구조화 출력(JSON 스키마, zod)으로 늘 같은 형태 → 계산 엔진이 바로 사용
  - 모델: Claude Opus 5.5(`claude-opus-5-5`), effort low
- AI가 틀릴 때의 대응
  - 추측 금지: 모르면 값을 비우고 '확인 필요' → 사용자에게 되물음
  - 범위를 벗어난 값(시급 0원, 주 52시간 초과 등)은 버리고 '확인 필요'로
  - 공고 안의 지시문은 따르지 않게 지시하고 자료로만 다룸(지시문 설계)
  - 근거에 이름·전화번호를 옮기지 않음, 입력 내용은 서버에 저장·기록하지 않음
  - 실패하면 이유와 재시도 안내, 직접 입력·예시로 계속
  - 모든 값을 사용자가 고칠 수 있음, 결과에 "AI가 생성한 내용이 포함되어 있습니다" 표시
  - 시험: 가상 공고 8건(항목 35개) 기대값 일치, 공고 아닌 글 거절. 재시험에서 '12월부터 3개월'을 1개월로 줄여 읽는 오류를 찾아 지시문 수정(`기획/AI_활용내역.md` ④)

## 04 서비스 구조

- 핵심 문장: 계산은 내 브라우저에서, 서버는 AI 읽기만 이어 줘요
- 구조도
  - 사용자 브라우저(휴대폰·PC): 화면 `app.js` / 계산 엔진 `engine.js`(순수 함수, 시험 172건) / 규칙표 `rules.json`(근거 조문·확인일·확인 수준) / 세션 저장소(탭을 닫으면 지워짐)
  - → 공고 사진·글만 → Vercel 서버 함수 `api/extract.js`(크기·횟수 제한, 값 정리, 저장·기록 안 함)
  - → Anthropic Claude API(Claude Opus 5.5, 구조화 출력)
  - ← 조건 5개 + 근거 + 확인 수준(JSON)
- 기술 스택(양식 표)
  - 프론트/클라이언트: HTML·CSS·JavaScript(ES 모듈, 프레임워크 없음), 휴대폰 우선 + PC 두 칸 화면, Pretendard
  - 백엔드/에이전트: Vercel 서버 함수(Node.js) + @anthropic-ai/sdk·zod. 계산 엔진·근무시간 비교·문구 조합은 브라우저에서 실행
  - AI 모델: Claude Opus 5.5(`claude-opus-5-5`), effort low, 구조화 출력
  - 외부 API: Anthropic Claude API(공공데이터 API는 쓰지 않음)
  - 데이터(출처·라이선스): 규칙표 = 법령·고시 원문(국가법령정보센터 등)을 팀이 정리, 확인일 2026. 11. 20.(법령·고시는 저작권법 제7조의 보호받지 못하는 저작물). 예시·시험 공고는 팀이 만든 가상 데이터
  - 배포 환경: Vercel(화면 + AI 서버 함수), 제출 주소 https://hankkeut-app.vercel.app
