[요약]
제품: 문턱 — 청년이 알바 공고나 제안 메시지를 올리면, 그 일을 했을 때 넘게 되는 제도 기준선과 손익을 계산하고 넘지 않는 근무 조건을 제안하는 AI 에이전트 웹 서비스.
범위: 제도 4개, 핵심 기능 3개, 화면 4개. 로그인 없음. 3일 안에 만드는 해커톤 MVP.
원칙: 조건을 읽고 되묻는 일은 AI가, 기준선 판정과 금액 계산은 규칙표를 읽는 코드가 한다.

[문서 작성 지침]
- 모든 문서는 한국어로 작성한다.
- 아래에 적힌 범위 밖의 기능을 추가하지 않는다. 추가가 필요해 보이면 넣지 말고 "범위 밖 제안"으로 따로 적는다.
- 화면은 4개를 유지한다.
- 불명확한 부분은 추측해서 채우지 말고 질문한다.
- 상세기능마다 동작 조건, 예외 처리, 완료 기준을 적는다.
- 기준 금액이나 계산식 수치를 임의로 적지 않는다. 수치가 필요한 곳은 "[규칙표 참조]"로 표기한다.

[대상 사용자]
- 구직촉진수당이나 훈련장려금을 받으면서 알바를 하려는 직업훈련생
- 부모의 건강보험 피부양자와 연말정산 부양가족으로 올라 있는 대학생·취업준비생
- 알바·프리랜서(3.3% 공제) 소득이 있는 만 19~34세 청년

[해결하려는 문제]
소득이 기준선을 넘으면 수당이 깎이거나 부모의 세금과 건강보험이 달라진다. 기준이 제도마다 다른 기관에 흩어져 있어, 청년은 새 알바를 해도 되는지와 얼마까지 벌어도 되는지를 스스로 판단하기 어렵다.

[다루는 제도 4개]
이 4개만 계산한다. 그 외 제도는 계산하지 않는다.
1. 부모 연말정산 부양가족 공제의 소득 요건
2. 건강보험 피부양자 소득 요건
3. 국민취업지원제도 구직촉진수당의 소득 발생 시 감액
4. 주 15시간 기준 (주휴수당, 4대보험 가입)

[핵심 기능 3개]
1. 조건 읽기
   - 입력: 알바 공고나 제안 메시지의 사진 또는 텍스트
   - AI가 시급, 주당 근무시간, 근무 기간, 급여 지급 방식을 추출한다
   - 소득 종류를 근로소득, 일용근로소득, 사업소득(3.3% 공제) 중 하나로 판별한다
   - 추출한 항목마다 원문의 어느 부분에서 읽었는지 근거를 함께 보여준다
   - 값이 없거나 모호한 항목은 추측하지 않고 사용자에게 질문한다
2. 기준선 판정
   - 사용자의 현재 상황(받는 수당, 부모 피부양자 여부, 올해 누적 소득)을 입력받는다
   - 제도별로 기준선을 넘는지, 몇 월에 넘는지, 넘으면 손익이 얼마인지 보여준다
   - 결과마다 확정, 추정, 확인 필요 중 하나를 표시한다
3. 대안 제안
   - AI 에이전트가 규칙 엔진을 여러 번 호출해 조건을 바꿔 가며 비교한다
   - 기준선을 넘지 않는 최대 근무시간을 찾는다
   - 넘는 경우, 얼마 이상 벌어야 전체적으로 이득인지 찾는다
   - 고용주에게 보낼 근무시간 조정 요청 문구를 만든다
   - 소득 신고 의무와 문의처를 안내한다

[우선순위]
- 필수 (없으면 제출 불가): 핵심 기능 1, 2, 3과 화면 4개, 아래 예외 처리 전부
- 권장: 결과 화면의 월별 누적 소득 타임라인, 법 개정안 기준 결과 병기
- 여유 시: 월별 소득 기록을 브라우저에 저장해 다음 방문 때 이어 보기

[화면 4개]
1. 올리기: 공고·메시지 사진 올리기 또는 텍스트 붙여넣기. 가상 샘플을 불러오는 버튼 3개.
2. 추출 확인: 추출된 조건 목록과 원문 근거, 수정 가능. 모호한 항목에 대한 질문.
3. 내 상황: 받는 수당, 부모 피부양자 여부, 나이, 올해 누적 소득을 고르는 짧은 입력.
4. 결과: 제도별 기준선 결과 카드, 월별 누적 소득 타임라인, 대안, 요청 문구 복사, 신고 안내.

[데이터 구조]
- 추출 결과: 시급, 주당 근무시간, 근무 요일, 근무 기간(시작·종료), 지급 방식 단서, 소득 종류(근로, 일용, 사업, 불명), 항목별 원문 근거, 항목별 확신 수준
- 사용자 상황: 나이, 받는 수당 종류, 부모 피부양자 여부, 부모 연말정산 부양가족 여부, 올해 누적 소득(소득 종류별), 부모 소득 구간(모름 선택 가능)
- 규칙표 항목: 제도명, 판정 조건, 기준값, 영향 계산 방식, 근거 조문과 출처 링크, 적용 연도, 확인일, 상태(확정 또는 개정 예정)
- 판정 결과: 제도명, 넘는지 여부, 넘는 시점, 손익(값 또는 범위), 표시 등급(확정, 추정, 확인 필요), 근거

[반드시 지킬 설계 원칙]
- 기준선 판정과 금액 계산은 AI가 하지 않는다. 코드로 된 규칙 엔진이 규칙표를 읽어 계산한다.
- 규칙표는 코드와 분리된 데이터 파일이다.
- 규칙표에 없는 제도를 물으면 결론을 내지 않고 "확인 필요"와 문의처를 안내한다.
- 법 개정이 진행 중인 기준은 현행 기준과 개정안 기준의 결과를 나란히 보여준다.
- 소득을 숨기거나 신고를 피하는 방법은 안내하지 않는다. 근무시간과 시기 선택만 다룬다.
- 모든 결과 화면에 "참고용이며 세무·법률 자문이 아님"과 AI가 생성한 내용임을 표시한다.

[예외 처리]
- 사진에서 조건을 읽지 못한 경우: 직접 입력으로 전환
- 소득 종류를 판별할 수 없는 경우: 사용자에게 질문 (예: 급여에서 3.3%를 떼는지, 4대보험을 떼는지)
- 규칙표에 없는 제도를 물은 경우: 확인 필요 안내
- 부모의 소득 구간을 모르는 경우: 손익을 범위로 표시
- AI 호출이 실패하거나 한도에 걸린 경우: 재시도 안내와 샘플 결과 보기

[시연 시나리오 3개 = 완료 기준]
아래 세 시나리오가 처음부터 끝까지 끊기지 않고 동작하면 완료다. 유저플로우와 와이어프레임은 이 시나리오를 기준으로 만든다.
A. 구직촉진수당을 받는 훈련생이 주말 카페 알바 공고 사진을 올린다. 조건이 추출되고, 수당 감액 결과와 일해도 총수입이 늘지 않는 구간이 표시되고, 수당이 유지되는 최대 근무시간이 제안된다.
B. 부모의 피부양자인 대학생이 "3.3% 떼고 지급"이라고 적힌 제안 메시지를 붙여 넣는다. 사업소득으로 판별되고, 피부양자 기준과 부모 공제 기준을 넘는 달이 표시되고, 넘지 않는 근무 조건이 제안된다.
C. 급여 지급 방식이 적히지 않은 공고를 올린다. 에이전트가 소득 종류를 되묻는다. 이어서 사용자가 청년월세지원에 대해 묻자 계산하지 않고 "확인 필요"와 문의처를 안내한다.

[이번 버전에서 만들지 않는 것]
회원가입과 로그인, 알림, 결제, 관리자 화면, 커뮤니티, 가구 소득 기준 제도(청년월세지원, 국가장학금 등)의 계산, 실제 신고 대행.

[기술·운영 조건]
- 모바일 우선 반응형 웹. 로그인 없이 바로 사용할 수 있어야 한다 (심사위원이 링크로 접속해 실행).
- 개인정보를 서버에 저장하지 않는다. 입력값은 브라우저 안에서만 유지한다.
- 시연은 가상 샘플 데이터로만 한다.
- AI 모델은 이미지 입력과 도구 호출을 지원하는 모델을 서버에서 호출한다. API 키는 서버 환경변수에만 둔다.

[원하는 산출물]
1. 요구사항 문서(PRD)
2. 기능명세: 기능, 상세기능, 동작 조건, 예외 처리, 완료 기준의 계층 구조
3. 유저플로우: 시나리오 A, B, C의 정상 흐름과 예외 흐름
4. 화면별 와이어프레임
