# 토스 UI/UX 레퍼런스 (문턱 디자인 개편용)

조사일 2026-11-20. 토스 공식 자료(앱인토스 개발자센터, 토스 디자인 시스템 문서, 토스피드 인터뷰)에서 모았습니다. 출처는 맨 아래에 있습니다.

> 주의: 토스의 **원칙과 방식**을 따르는 것이지 토스처럼 **보이게** 만드는 게 아닙니다. 토스 로고, 토스 전용 서체(Toss Product Sans), 토스 파란색(#3182F6)을 대표색으로 쓰는 것은 피합니다. 문턱은 지금의 초록을 대표색으로 유지하고, 한글 서체는 무료 공개 서체인 Pretendard를 씁니다. TDS 피그마 UI 키트는 앱인토스용 라이선스라 가져다 쓰지 않습니다.

## 1. 단순함 원칙

| 원칙 | 내용 | 출처 |
|---|---|---|
| 단순함의 정의 | 설명 없이 본능적으로 이해할 수 있는 상태 | 토스피드 ① |
| 한 화면에 한 가지 | 화면마다 해야 할 일은 하나, 누를 버튼도 하나 | 토스피드 ①, 디아이투데이 |
| 첫 화면은 더 단순하게 | 첫 화면에 더 넣어도 사용자는 알아채지 못한다는 실험 결과 | 토스피드 ① |
| 경고는 미리 채우지 않기 | 실수했을 때만 무엇이 잘못됐는지 알려 주고 다시 하게 | 토스피드 ① |
| 요구는 마지막까지 미루기 | 인증·입력·동의는 없앨 방법부터 찾고, 필요하면 맨 뒤로 | 토스피드 ①, 앱인토스 ④ |
| 빼는 게 답일 수 있다 | 무언가를 더하기보다 빼는 게 더 좋은 해결책일 수 있음 | 앱인토스 ⑤ |
| 다른 앱 베끼지 않기 | 다른 앱의 구성을 가져와 문구만 바꾸지 않음 | 앱인토스 ③⑤ |

## 2. 화면 구성

- 사용자는 처음부터 읽지 않고 **큰 글자, 이미지, 버튼부터 훑어봅니다.** 제목, 설명, 결과는 중요도에 따라 크기를 다르게 합니다. (앱인토스 ③)
- **첫 화면에서 가장 먼저 할 일이 바로 보여야 합니다.** (앱인토스 ⑤)
- 입력칸과 버튼은 **사용 순서대로** 둡니다. (앱인토스 ③⑤)
- 그래픽은 **한 화면에 가장 중요한 하나만 크게**, 나머지는 아이콘으로 둡니다. 그래픽 때문에 핵심 정보나 버튼이 아래로 밀리면 안 됩니다. (앱인토스 ①)
- **아이콘·이모지는 한 번에 하나만.** 둘 이상 나란히 쓰지 않습니다. 아이콘 크기는 24~40px. (앱인토스 ①)
- 같은 역할의 버튼과 카드는 **모든 화면에서 색과 모양을 똑같이** 합니다. (앱인토스 ③⑤)
- 색과 장식은 **제목이나 결과를 강조할 때만** 씁니다. 배경색이나 장식이 제목보다 먼저 눈에 띄면 안 됩니다. 의미 없는 그래픽, 반짝이 효과, 과한 그라데이션은 쓰지 않습니다. (앱인토스 ①③)
- 영역 구분은 그림자보다 **배경색 차이**로 합니다(흰 카드 + 연회색 배경). (제3자 분석)
- 기다릴 필요가 없는데 로딩 애니메이션을 쓰지 않습니다. 상황에 맞지 않는 느낌표 아이콘도 쓰지 않습니다. (앱인토스 ①)

## 3. 버튼

- **버튼 이름에 누르면 일어나는 일을 씁니다.** "확인" → "결과 보기", "저장" → "오늘 기록 저장하기", "완료" → "예약 확정하기" (앱인토스 ③⑤)
- 버튼만 보고도 결과를 예측할 수 있어야 합니다. 버튼 위에 같은 설명을 반복하거나 과장된 문구를 두지 않습니다. (앱인토스 ①)
- 주요 버튼은 **화면 맨 아래에 고정**합니다(BottomCTA). 하나짜리와 두 개짜리가 있습니다. 아래 여백은 기기 안전 영역 또는 최소 20px. (TDS)
- 버튼 종류: **진한 버튼(fill)** = 주요 행동, **연한 버튼(weak)** = 보조 행동. 색은 기본(primary), 어두운(dark), 위험(danger), 밝은(light). (TDS)
- 두 버튼일 때 왼쪽은 **"취소"가 아니라 "닫기"**. "취소"는 작업 자체를 취소한다고 오해할 수 있습니다. (앱인토스 ①, 토스피드 ②)
- 버튼 문구 습관: 행동 하나면 "~하기", 다음 화면으로 넘기면 "다음"이나 "확인", 미룰 때는 "다음에". (토스피드 ②)

## 4. 글쓰기 (UX 라이팅)

| 규칙 | 예 | 출처 |
|---|---|---|
| 모든 문구는 해요체 | "보냈어요", "확인해요" | 앱인토스 ① |
| 능동형으로 | "완료되었습니다" → "다 했어요" | 앱인토스 ① |
| 긍정 표현 우선 | "없습니다"보다 "있어요" 쪽으로. 단 이용 불가는 분명히 부정문 + 이유 | 앱인토스 ① |
| 과한 존댓말 빼기 | "~하시겠어요?", "~이신가요?", "~시" 줄이기 | 앱인토스 ① |
| 명사 나열 풀기 | "소득 발생 시 신고 필요" → "돈을 벌면 신고해야 해요" | 앱인토스 ① |
| 잡초 뽑기 | 빼도 뜻이 그대로인 단어는 뺀다 | 토스피드 ② |
| 전문 용어 없애기 | "Zero Jargon". 어려운 말은 쉬운 말로 | 토스피드 ②, ① |
| 한 사람이 말하듯 | 화면마다 말투를 하나로 | 토스피드 ② |
| 결과에는 의미를 같이 | "72점" → "72점, 평균보다 조금 높아요" | 앱인토스 ③⑤ |
| 빈 화면엔 이유를 | "데이터가 없습니다" → "아직 기록이 없어요. 첫 기록을 남기면 여기에 보여 드릴게요" | 앱인토스 ③⑤ |
| 결과가 바뀌면 왜 바뀌었는지 | 입력에 따라 결과가 달라지면 이유를 함께 | 앱인토스 ③⑤ |
| 공감하는 말투 | "대출 잔액이 줄었으니 확인해 보세요" → "갚느라 고생 많으셨어요" | 토스피드 ② |
| 요청엔 이유를 | "알림을 허용해 주세요" → "예약 하루 전에 알림으로 알려 드릴게요" | 앱인토스 ④ |
| 자극·애원 금지 | 과한 감정 표현, 부담 주는 표현은 다크패턴 | 앱인토스 ① |

## 5. 숫자

- 실시간으로 바뀌는 숫자, 표 안의 숫자는 **고정폭 숫자**(CSS `font-variant-numeric: tabular-nums`). 크게 강조하는 숫자 하나는 일반 폭. (토스피드 ⑤)
- %, 쉼표, +, − 같은 기호는 잘 보이게 합니다. (토스피드 ⑤)

## 6. 하지 말아야 할 것 (다크패턴)

- 앱을 열자마자 화면을 가리는 안내창(알림 동의 포함)
- 거절할 방법이 없는 버튼
- 예상하지 못한 때 뜨는 전면 광고
- 결과를 예측할 수 없는 모호한 버튼 문구
- 애원하거나 불안하게 만드는 문구
- 첫 화면에서 로그인·동의 요구 (토스 내부 수치: 진입 직후 로그인 요청 시 완료율 49.6%)

(앱인토스 ①④⑤)

**빨강**: red50 `#FFEEEE` · red500 `#F04452` · red600 `#E42939`
**초록**: green50 `#F0FAF6` · green500 `#03B26C` · green700 `#029359`

## 9. 목록 한 줄 (ListRow)

- 구조: **왼쪽(아이콘) | 가운데(글 1~3줄) | 오른쪽(값·스위치·화살표)**
- 위아래 여백 8 / 12(기본) / 16 / 24px, 좌우 여백 20 / 24(기본)px
- 구분선은 왼쪽을 들여서(indented) 긋는 게 기본

(TDS ListRow)

## 문턱에 적용할 것 (팀 검토용)

1. **한 화면에 한 가지**: "내 상황" 화면의 질문 묶음을 1~2개씩 나눠 넘기는 방식 검토
2. **하단 고정 버튼**: 모든 화면의 주요 버튼을 화면 아래에 고정. 버튼 이름은 "계산하기" → "결과 보기"처럼 결과를 말하게
3. **해요체·능동형 전면 적용**: 지금 남은 "~함", "~음", "~습니다" 문구 정리
4. **결과에 의미 붙이기**: "+81만 원" 옆에 "지금보다 한 달에 이만큼 늘어요"처럼
5. **회색 단계와 글자 크기는 TDS 값을 기준으로**: 본문 17px, 작은 글 15px, 제목 22~30px
6. **아이콘은 한 줄에 하나**: 시안의 이모지는 같은 모양의 선 아이콘으로 바꾸는 것 검토
7. **대표색은 문턱 초록 유지**, 빨강(줄어듦)·초록(늘어남)·파랑(신고)만 의미 색으로
8. **경고는 미리 깔지 않기**: 면책 문구는 첫 화면과 결과 화면에 한 줄만
