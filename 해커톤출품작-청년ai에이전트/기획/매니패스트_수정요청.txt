==============================
1. 공통 수정
==============================
1-1. 서비스 이름을 "알바체크"에서 "문턱"으로 바꾼다. 프로젝트 이름 칸에도 한 줄 설명 대신 "문턱"을 넣는다.
1-2. 화면을 20개에서 11개로 정리한다. 화면 구성은 3번 항목을 따른다. 흐름은 4단계(올리기 → 확인 → 내 상황 → 결과)를 유지한다.
1-3. 모든 화면을 휴대폰 화면 우선으로 다시 그린다. 왼쪽 메뉴(홈, 새 분석 시작, 규칙 관리)를 없애고, 상단에는 서비스 이름, 단계 표시(1/4 ~ 4/4), "내 기록" 링크만 둔다.
1-4. 상단의 알림(종) 아이콘과 프로필 아이콘을 삭제한다. 로그인과 계정 기능이 없기 때문이다.
1-5. 와이어프레임과 문서에 들어 있는 기준 금액, 계산 결과, 법 조문 번호를 전부 지우고 "[규칙표 참조]"로 바꾼다. 3-12번 항목에 지워야 할 값을 적었다.
1-6. 모든 결과 영역 하단에 다음 두 문구를 유지한다: "참고용 계산이며 세무·법률 자문과 행정기관의 최종 판단을 대체하지 않습니다", "AI가 생성한 내용이 포함되어 있습니다".
1-7. 모든 화면은 6번 항목의 시연 시나리오 A, B, C 중 하나 이상에서 실제로 거치는 화면이어야 한다. 어느 시나리오에도 쓰이지 않는 화면은 만들지 않는다.

2. 삭제할 것
==============================
2-1. 로그인/회원가입 화면(02)과 유저플로우의 "진입·인증" 구간의 로그인 분기. 접속하면 바로 시작 화면이 나온다.
2-2. 규칙 관리 화면(19), 규칙 등록 화면(20)과 유저플로우의 "규칙·근거 관리(관리자)" 구간 전체. 규칙표는 화면이 아니라 데이터 파일로 관리한다.
2-3. 사용자 역할에서 "규칙 및 근거 관리자", "계산 결과 검토자"를 삭제한다. 역할은 "청년 사용자" 하나만 남긴다.
2-4. 공고 링크 입력 기능 전체. 조건 입력 화면의 "링크 입력" 선택지와 공고 링크 입력란, 유저플로우의 "공고 링크 입력", "링크 읽기 성공?" 분기, 기능명세 REQ-001의 "공고 링크 공유" 관련 문장과 수용 기준 4번의 링크 관련 내용을 삭제한다.
2-5. 파일 업로드 형식에서 PDF와 Word를 삭제한다. 이미지(사진, 스크린샷)만 받는다.
2-6. 원문 대체 입력 안내 화면(07). 사진에서 조건을 읽지 못하면 추출 확인 화면 안에서 안내 문구와 직접 입력 전환 버튼을 보여준다.
2-7. 정보 부족 안내 화면(10), 계산 중 화면(11), 계산 보류 안내 화면(13), 지원 범위 외 안내 화면(14). 별도 화면이 아니라 해당 화면 안의 상태로 표시한다(3번 항목 참조).
2-8. 개인 조건 입력 화면의 "가구 합산 연소득", "부모와 동거 여부", "피부양자 연간 소득 기준 초과 여부", "월 평균 근무 시간" 입력란. 제도 계산에 쓰지 않는 값이다.
2-9. 요구사항 문서의 카테고리 "금융 / 재테크"를 "생활 / 공공 정보"로 바꾼다.

3. 화면 11개 구성
==============================
우선순위: 필수 8개(화면 1, 2, 3, 4, 5, 7, 8, 10), 권장 2개(화면 6, 9), 여유 시 1개(화면 11).

[화면 1. 시작] 기존 01을 고친다. (필수)
- 서비스 한 줄 소개: "일을 더 해도 되는지, 넘게 되는 기준선과 손익을 계산해 드립니다."
- 다루는 제도 목록과 "계산하지 않는 제도는 안내만 합니다"라는 설명.
- "새 계산 시작" 버튼.
- 가상 샘플로 바로 체험하기 버튼 3개: "주말 카페 알바 공고", "3.3% 떼는 제안 메시지", "지급 방식이 없는 공고".
- 로그인 버튼이나 가입 유도 문구는 넣지 않는다.

[화면 2. 올리기] 기존 04를 고친다. (필수, 1/4단계)
- 입력 방식은 세 가지: 사진 올리기, 공고·메시지 붙여넣기, 직접 입력. 한 번에 한 방식만 펼쳐서 보여준다. (현재 화면은 세 입력란과 직접 입력 양식이 모두 펼쳐져 있다.)
- 직접 입력 항목: 시급, 주당 근무시간, 근무 요일, 근무 시작일과 종료일(또는 기간), 급여 지급 방식(4대보험 공제 / 3.3% 공제 / 모름).
- 실제 개인정보가 담긴 사진은 올리지 말라는 안내 문구를 넣는다.

[화면 3. 추출 확인] 기존 05를 유지한다. (필수, 2/4단계)
- 항목별 확정·추정·확인 필요 표시와 원문 발췌를 유지한다.
- 소득 종류 선택지는 근로소득, 일용근로소득, 사업소득(3.3%), 모름으로 한다.
- 사진에서 조건을 읽지 못한 경우: 이 화면에 안내 문구와 "직접 입력으로 전환" 버튼을 보여준다.
- "개인·수급 조건 입력으로 건너뛰기" 버튼은 삭제한다. 확인 필요 항목이 있으면 화면 4로, 없으면 화면 5로 간다.

[화면 4. 추가 질문] 기존 06을 유지한다. (필수, 2/4단계)
- AI 에이전트가 모호하거나 빠진 항목을 한 번에 하나씩 질문한다. 질문마다 왜 묻는지 한 줄로 설명하고 선택지를 준다. 예: "급여에서 무엇을 떼고 받나요? (소득 종류에 따라 적용되는 기준이 달라집니다) 4대보험 / 3.3% / 모름".
- 남은 질문 수를 표시한다.
- "모름"을 고르면 그 항목이 영향을 주는 제도는 확인 필요로 표시된다는 안내를 보여준다.
- 필수 질문에 모두 답해야 다음 단계로 간다.

[화면 5. 내 상황] 기존 08을 고친다. (필수, 3/4단계)
- 입력 항목은 다음만 둔다.
  · 만 나이
  · 구직촉진수당을 받고 있는지 (예 / 아니오 / 신청 중)
  · 부모의 건강보험 피부양자인지 (예 / 아니오 / 모름)
  · 부모의 연말정산 부양가족으로 올라 있는지 (예 / 아니오 / 모름)
  · 올해 이미 번 소득 (소득 종류별 금액, 없으면 0)
  · 부모의 연 소득 구간 (구간 선택, 모름 가능)
  · 그 밖에 받고 있는 지원 (선택. 규칙표에 없는 제도는 계산하지 않고 안내만 한다)
- 예/아니오 항목은 라디오 버튼 하나가 아니라 선택지 버튼으로 표시한다. (현재 화면은 "여부" 항목이 라디오 버튼 한 개로 그려져 있다.)
- 값이 부족한 항목 옆에 "이 값이 없으면 ○○ 제도는 범위로만 표시됩니다"라고 안내한다. (기존 10의 내용)

[화면 6. 입력 요약 확인] 기존 09를 유지한다. (권장, 3/4단계)
- 일자리 조건과 내 상황을 한 번에 보여주고, 어느 값이 어느 제도 계산에 쓰이는지 표시한다.
- 항목별 "수정" 버튼으로 화면 3 또는 화면 5로 돌아갈 수 있다.
- "계산하기" 버튼.
- 구현 시간이 모자라면 이 화면을 생략하고 화면 5 하단에 요약을 둔다.

[화면 7. 결과] 기존 12를 고친다. (필수, 4/4단계)
- 계산 중에는 이 화면에 로딩 표시를 보여준다. (기존 11의 내용)
- 구역 1. 요약: 추가 소득, 줄어드는 수당과 늘어나는 부담, 실질 순소득.
- 구역 2. 제도별 카드: 부모 연말정산 공제, 건강보험 피부양자, 구직촉진수당, 주 15시간 기준. 카드마다 기준선, 넘는지 여부, 넘는 시점, 손익, 확정·추정·확인 필요 표시를 둔다. 제도가 추가되면 카드만 늘어나는 구조로 그린다.
- 구역 3. 월별 누적 소득 타임라인: 1월~12월 누적 소득과 기준선을 넘는 달을 표시한다.
- 카드의 상태 표시: 계산 보류(사유와 다음 확인 행동), 지원 범위 외(계산하지 않는다는 안내와 문의처). (기존 13, 14의 내용)
- 법 개정이 진행 중인 기준은 카드 안에 현행 기준 결과와 개정안 기준 결과를 나란히 표시한다.
- 하단 버튼: "대안 비교 보기", "근거와 다음 행동 보기".

[화면 8. 대안 비교] 기존 15를 고친다. (필수)
- AI 에이전트가 찾은 대안을 카드로 비교한다: "기준선을 넘지 않는 최대 근무시간", "넘더라도 총수입이 늘어나는 조건", "원래 조건".
- 카드 항목: 근무시간, 추가 소득, 수당 변화, 실질 순소득, 넘는 기준선, 확정·추정·확인 필요 표시.
- 에이전트가 어떤 조건들을 바꿔 가며 비교했는지 한두 줄로 보여준다.
- 필수 정보가 부족해 대안을 만들 수 없으면 대안을 만들지 않고 부족한 정보를 안내한다.

[화면 9. 대안 상세와 요청 문구] 기존 16을 고친다. (권장)
- 선택한 대안의 월별 변화와 제도별 영향.
- 고용주에게 보낼 근무시간 조정 요청 문구와 복사 버튼.
- 구현 시간이 모자라면 이 화면을 생략하고 화면 8의 카드를 펼쳐서 요청 문구를 보여준다.

[화면 10. 근거와 다음 행동] 기존 17과 18을 합친다. (필수)
- 제도별 근거: 근거 조문, 적용 연도, 확인일, 출처 링크, 규칙 상태(확정 또는 개정 예정).
- 계산에 사용한 조건과 부족했던 정보.
- 소득 신고 의무 안내.
- 공식 문의처: 고용노동부 1350, 국민건강보험공단 1577-1000, 국세청 126.
- "조건 바꿔서 다시 계산" 버튼.

[화면 11. 내 기록] 기존 03(홈)을 바꿔서 쓴다. (여유 시)
- 올해 월별 소득을 직접 기록하고, 제도별 기준선까지 남은 금액을 보여준다.
- 이전 계산 결과 목록.
- 기록은 브라우저에만 저장된다는 안내. 로그인은 없다.

3-12. 와이어프레임에서 지워야 할 값 (모두 "[규칙표 참조]" 또는 빈 예시로 교체)
- 구직촉진수당 "기준선 월 600,000원", "월 소득이 50만 원을 초과하면 수급 자격 중단", "초과 — 수당 지급 중단 예상"
- 부모 세금 공제 "연 100만 원 이하", "초과 — 부모 연말정산 공제 불가"
- 건강보험 피부양자 "연 2,000만 원 이하"
- 시급 "9,860원", "2024년 최저임금"
- 계산 근거 "고용보험법 §40 기준 적용", "소득 기준 초과 시 §41 적용"
- 요약의 금액(780,000원, 312,000원, 468,000원, 1,850,000원, 420,000원, 1,430,000원)과 대안 카드의 금액, "소득세 +2.4만 원", "소득세 +6.1만 원", "월 최대 50만 원 손실"
- "훈련 참여율 80% 이상 유지 필요"

4. 다루는 제도
==============================
4-1. 계산하는 제도(필수) 4개: 부모 연말정산 부양가족 공제, 건강보험 피부양자, 구직촉진수당, 주 15시간 기준(주휴수당·4대보험).
4-2. 원문 확인 후 추가할 제도(확대 후보) 3개: 근로장려금, 실업급여, 훈련장려금. 문서에는 "원문 확인이 끝난 제도만 규칙표에 추가한다"고 적고, 확인 전에는 계산 대상으로 쓰지 않는다.
4-3. 확대 후보나 그 밖의 제도를 사용자가 받고 있다고 답하면, 규칙표에 없는 동안에는 "이번 버전에서 계산하지 않는 제도입니다"라는 확인 필요 안내와 문의처만 보여준다.
4-4. 기존 문서와 화면에서 "훈련 관련 지원"을 계산 대상처럼 쓴 곳(REQ-003의 대상 제도, 개인 조건 화면, 결과 화면의 카드)을 위 기준에 맞게 고친다.

5. 기능명세와 요구사항 문서 수정
==============================
5-1. REQ-001: 입력 방식을 "사진 올리기, 공고·메시지 붙여넣기, 직접 입력"으로 고친다. 수용 기준에 "가상 샘플 3개를 불러와 바로 시연할 수 있다"를 추가한다.
5-2. REQ-002: 질문 항목을 화면 5의 입력 항목과 일치시킨다.
5-3. REQ-003: 대상 제도를 4번 항목과 일치시킨다. 수용 기준에 "규칙마다 기대값 테스트가 있고 모두 통과한다"를 추가한다.
5-4. REQ-004: 수용 기준에 "대안은 AI 에이전트가 규칙 엔진을 여러 번 호출해 조건을 바꿔 가며 찾는다", "고용주에게 보낼 근무시간 조정 요청 문구를 제공한다"를 추가한다.
5-5. REQ-005: 수용 기준 3번(관리자 또는 검토자가 규칙을 등록)을 "규칙표는 코드와 분리된 데이터 파일이며, 규칙마다 근거 조문·적용 연도·확인일·상태를 가진다"로 고친다.
5-6. 요구사항을 2개 추가한다.
  · REQ-007 품질 검증: 가상 사례 평가 세트로 조건 추출과 소득 종류 판별의 정확도를 측정하고 결과를 기록한다.
  · REQ-008 장애 대응: AI 호출이 실패하거나 한도에 걸리면 재시도 안내와 샘플 결과 보기를 제공한다.
5-7. 요구사항마다 우선순위를 표시한다. 필수: REQ-001~006, REQ-008. 권장: REQ-007, 월별 누적 소득 타임라인, 개정안 기준 병기. 여유 시: 내 기록(브라우저 저장).

5-9. 리스크에 "법 개정이 진행 중인 기준은 현행과 개정안을 나란히 표시한다"를 대응 방안으로 추가한다.
5-10. 디바이스를 "스마트폰 우선, 컴퓨터 웹 브라우저 지원"으로 고친다.
5-11. "개인정보를 서버에 저장하지 않고 입력값은 브라우저 안에서만 유지한다", "소득을 숨기거나 신고를 피하는 방법은 안내하지 않는다"를 원칙으로 추가한다.

==============================
6. 유저플로우 수정
==============================
6-1. 구간을 다시 그린다: 시작 → 올리기 → 추출 확인 → 추가 질문 → 내 상황 → 입력 요약 → 결과 → 대안 비교 → 대안 상세 → 근거와 다음 행동. 내 기록은 상단 링크로 어느 화면에서나 갈 수 있다.
6-2. 아래 세 시나리오의 흐름이 모두 표현되어야 한다.
A. 구직촉진수당을 받는 훈련생이 주말 카페 알바 공고 사진을 올린다. 조건이 추출되고, 수당 감액 결과와 일해도 총수입이 늘지 않는 구간이 표시되고, 수당이 유지되는 최대 근무시간이 제안된다.
B. 부모의 피부양자인 대학생이 "3.3% 떼고 지급"이라고 적힌 제안 메시지를 붙여 넣는다. 사업소득으로 판별되고, 피부양자 기준과 부모 공제 기준을 넘는 달이 표시되고, 넘지 않는 근무 조건이 제안된다.
C. 급여 지급 방식이 적히지 않은 공고를 올린다. 추가 질문 화면에서 소득 종류를 되묻는다. 내 상황 화면에서 사용자가 청년월세지원을 받고 있다고 답하면 계산하지 않고 "확인 필요"와 문의처를 안내한다.
6-3. 예외 흐름 4개를 표시한다: 사진 인식 실패 → 직접 입력 전환 / 소득 종류 불명 → 추가 질문 / 규칙표에 없는 제도 → 확인 필요 안내 / AI 호출 실패 → 재시도와 샘플 결과.
