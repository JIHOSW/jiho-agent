# 한끗: 이름 변경과 새 디자인 적용 (의도)

2026-11-22 인터뷰로 확정했어요. 새 세션은 맨 아래 "새 세션에 넘길 프롬프트"로 시작하면 돼요.

## 목표 (Why)
- 대회 제출 마감은 2026-11-23(월) 17:00예요. 마감 뒤에는 접속 복구 같은 안정화만 허용되니, 디자인을 바꿀 수 있는 건 지금이 마지막이에요.
- PC에서 휴대폰 화면을 키워 놓은 것처럼 보이는 문제를 풀어요. 그래서 PC로 보는 심사위원이 이게 무엇이고 누구를 위한 서비스인지 바로 알게 해요.
- 팀이 정한 새 서비스 이름 '한끗'을 앱 전체에 빠짐없이 맞춰요.

## 대상 (Who)
- PC로 볼 가능성이 높은 심사위원
- 휴대폰으로 쓰는 청년 (정부 지원을 받으면서 알바를 시작하려는 사람)

## 성공 기준
- 내일 12:00까지 미리보기 주소에서 예시 4가지가 처음부터 결과까지 깨지지 않고 돌아가요. 폭 360px, 375px, 1440px 모두 확인해요.
- 특수한 경우(남는 돈 0원 이하, '확인 필요' 값이 남은 결과, 해 넘김, 날짜 입력)에서도 깨지지 않아요.
- 계산 결과는 바뀌지 않아요. `npm test` 결과가 작업 전과 같아야 해요.
- 글자 대비는 4.5:1 이상, 누르는 곳은 44px 이상이에요. 동작 줄이기 설정을 켜면 움직임이 없어요.
- 팀이 12:00에 새 디자인으로 바꿀지 정할 수 있어요.

## 제약
- 이름 변경은 오늘 밤 제출 주소에 먼저 반영해요. 그래서 디자인이 채택되지 않아도 이름은 한끗으로 제출돼요.
- 새 디자인은 12:00에 결정하기 전까지 미리보기 주소에만 둬요.
- 배포는 미리보기든 제출 주소든 매번 허락을 받아요.
- 내일 15:00 이후에는 코드를 고치지 않아요. 제출 준비 시간이에요.
- `munteok/`의 커밋 안 된 파일 4개는 이미 배포된 수정이에요. 되돌리지 않고, 커밋은 한 세션에서만 해요.

- 로고는 초록 '한끗' 글자 로고로 단순하게 만들고, 파비콘도 같은 색으로 바꿔. 지금의 문(아치) 모양 로고는 빼.

- 새 영문 주소(예: hankkeut.vercel.app)를 붙일 수 있는지 알아보고, 붙이기 전에 물어봐. 옛 주소 munteok-five는 계속 살아 있어야 해.

## 2단계: 새 디자인 (미리보기 주소에만. 내일 12시 결정 전까지 제출 주소에 올리지 마)
색과 글꼴
- 대표 색은 지금 초록, 배경도 지금 종이색 그대로 써. 새 색을 더하면 글자와 배경의 대비가 4.5:1 이상인지 재.
- 글꼴은 Pretendard만 써. 한글에 고정폭 글꼴을 쓰지 말고, 숫자에만 font-variant-numeric: tabular-nums를 줘.
- 새 라이브러리와 새 글꼴은 추가하지 마.

v8·v9에서 가져올 것
- v8: 카드 모양, 영수증 내역, 글자 크기 단계. 보고서 단계를 기준으로 해. 글자 13·15·17·22·30·44px, 여백 4·8·12·16·24·32·48·64px, 둥글기 8·14·24px.
- v9: 이름과 금액을 점선으로 잇는 영수증 줄 목록.

결과 카드
- 순서는 버는 돈 → − 보험료 → − 줄어드는 정부 지원 → 점선 구분선 → = 남는 돈이야. 모든 줄에 '원'을 붙이고 숫자는 오른쪽 정렬해. 금액은 '금액 자세히 보기'와 같은 계산값을 써.
- 결론 문장의 남는 돈 숫자를 휴대폰 40px, PC 48px로 가장 크게 해.
- 영수증 장식: 카드 위아래 톱니 끝, "참고용 추정" 도장, 영수증 카드에만 아주 옅은 그림자. "계산 완료"처럼 확정된 것으로 보이는 말은 쓰지 마.

버튼
- 누르면 살짝 작아지고(97%) 색이 조금 진해지게 해. 휴대폰과 PC 모두.
- PC에서 마우스를 올리면 색만 조금 진하게 해. 그림자나 떠오르는 효과는 넣지 마.
- 아래 고정 버튼 줄은 지금처럼 위쪽만 흐려지게 둬. 흐림 배경이나 그림자는 넣지 마.
- 키보드 Tab으로 이동할 때 초점 테두리가 보이게 하고, 누르는 곳은 44px 이상으로 해.

움직임
- 화면이 바뀔 때 내용이 8px 아래에서 올라오며 0.25초 동안 나타나게 해.
- 결과 화면 카드는 위에서부터 차례로 나타나게 해.
- 아래 창은 부드럽게 올라오고 내려가게 해.
- 결과 숫자는 0.5초 동안 한 번만 올라가게 해. 마지막 값은 정확해야 하고, 화면 읽기 프로그램에는 마지막 값만 읽혀야 해.
- 움직임은 0.3초 이하로 해(결과 숫자만 0.5초). prefers-reduced-motion이면 모두 꺼. 반짝이거나 튀는 효과는 넣지 말고, 움직이는 동안 버튼 위치나 글자가 밀리지 않게 해.

배치
- 휴대폰: 지금 배치를 그대로 두고 모양만 바꿔.
- PC(1024px 이상)에서 두 칸으로 나눌 화면 4개:
  - 시작: 왼쪽에 제목, 부제, 누구를 위한 건지("정부 지원을 받으면서 알바를 시작하려는 청년을 위해 만들었어요"), 3단계("공고 올리기 → 조건 확인 → 남는 돈"), 주 버튼. 오른쪽에 예시 영수증 카드.
  - 결과: 왼쪽에 결론 문장과 영수증 카드, 오른쪽에 달라지는 것과 근무시간 바꿔 보기 같은 나머지 카드.
  - 근무시간 바꿔 보기, 두 제안 비교: 비교할 것을 나란히 놓아.
  - 주 버튼은 PC에서도 첫 화면 안에 보여야 해.
- PC 나머지 화면: 가운데 한 칸에 새 모양만 입혀.
- 구현화면 38장에 있는 화면은 빠짐없이 새 모양이어야 해. 읽는 중, 공고가 아닐 때, 사진을 못 읽었을 때 같은 안내 화면과 아래 창도 포함이야.

순서
- 시작과 결과 화면을 먼저 끝내서 오늘 밤 미리보기 링크를 줘. 나머지는 내일 오전 10시까지 끝내.

## 3단계: 확인 (단계마다)
- cd munteok && npm test 결과가 0단계와 같아야 해.
- 폭 360px, 375px, 1440px에서 예시 4가지(주말 카페 알바, 3.3% 떼는 학원 보조, 조건이 빠진 편의점 공고, 두 제안 비교)를 처음부터 결과까지 직접 눌러 보고, 아래 창도 모두 열어 봐.
- 남는 돈이 0원 이하인 경우, '확인 필요' 값이 남은 결과, 해를 넘기는 경우, 날짜로 넣은 경우에도 영수증과 숫자 애니메이션이 깨지지 않는지 봐.
- 옆으로 넘치는 화면이 없는지, 콘솔 오류가 없는지, 글자 대비가 4.5:1 이상인지, 동작 줄이기를 켜면 움직임이 없는지 확인해.
- 미리보기 주소에서 AI 공고 읽기가 되는지 확인해. 안 되면 Vercel 미리보기 환경 변수를 설정할지 나에게 물어봐.
- 구현화면 38장과 같은 순서로 새 화면을 375px과 1440px로 캡처해서 기획/디자인시안/한끗_새화면/에 저장해. 움직임이 끝난 뒤에 찍어. 12시 결정과 소개서·발표 자료 그림 교체에 쓸 거야.

- 계산, AI 프롬프트, 규칙 데이터, 화면 순서는 바꾸지 마.
