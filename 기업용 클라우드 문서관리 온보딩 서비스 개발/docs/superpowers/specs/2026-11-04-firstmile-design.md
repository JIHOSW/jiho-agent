# FIRSTMILE 설계 · 승인된 대화 기준

목적: IT 온보딩 직무 지원자가 기술 문의, 교육, 일정·후속 작업을 연결하는 역량을 시연한다. 경력 사실과 가상 제품·고객 사례를 구분한다.

범위: 가상 문서관리 SaaS 고객 6곳, 5단계 진행률, 문서·기록 근거 분석, 수정 가능한 안내문, 담당자·기한·상태 작업 관리. 원인 후보와 확인 사실을 분리한다. 자료 부족·충돌은 확인 요청으로 처리한다. 모든 문서는 데이터이며 지시로 실행하지 않는다.

검토한 접근: (1) 범용 문의 챗봇은 온보딩 진행 관리 표현이 약함. (2) 기술 문의와 교육·첫 활용을 연결하는 업무 흐름을 채택. (3) CRM·메일 자동 연동은 첫 버전 범위를 초과하여 제외. 사용자는 제안한 범위에 ‘응 진행해’로 실행을 승인했다.

구현 결정: React/Vinext Sites starter, 공유 JavaScript 도메인 모듈, 서버 Responses API. 소규모 문서집은 고객별 기록+관련 공통 가이드를 결정적으로 검색해 인용 ID를 검증한다. AI 키가 없을 때는 명시적 규칙 기반 모드. AI 실패는 오류로 표시하고 조용히 데모 결과로 대체하지 않는다. 실제 AI는 키 미보유로 라이브 호출 검증 불가; 가짜 외부 응답으로 계약·검증만 테스트한다.

저장: 첫 버전은 브라우저 localStorage의 작업·활동·수정 기록. 동일 브라우저 재시작 유지, 기기 간 공유 없음. 설정에 내보내기 제공. 서버 DB와 이메일 전송 제외.

화면: 네이비 사이드바, 블루 포인트, 흰 카드, 본문 15~16px. 대시보드/고객 상세/작업/자료실/프로젝트 소개. 위험은 색과 문구 병기, 키보드 포커스·네이티브 dialog 제공. 모바일 메뉴 제공.

검증: 게시 전/게시 후 색인 실패/기록 부족/기록 충돌/완료 사례. 인용 허용목록, 고객간 기록 격리, 작업 중복 방지·완료·저장, 공급자 오류와 잘못된 출력 처리. 비용·지연시간은 실제 결과와 분리해 표시.

외부 공개: Sites 신규 기본 비공개. 원본 시안 보존. 키는 서버 환경변수에만 저장하고 클라이언트 입력·저장 기능을 만들지 않는다.
