# FIRSTMILE의 솔루션 가정·전체 프로세스·근거 확인

## 무엇을 공급한 상황인가?

기업에 계정·문서함·접근 권한·문서 이관·게시·검색·버전관리를 제공하는 가상의 클라우드 문서관리 SaaS를 도입한 상황입니다. 실제 특정 회사의 제품을 구현하거나 연결한 것은 아닙니다. FIRSTMILE은 그 제품 자체가 아니라 공급사 내부의 온보딩 담당자가 고객의 첫 사용을 지원하는 별도 업무 도구입니다.

주요 역할은 공급사 온보딩 담당자, 고객사 관리자, 실제 사용자, 기술 담당자입니다. 고객별 첫 활용 목표를 합의한 뒤 설정·교육·문제 해결·실사용 확인을 연결합니다.

## 전체 흐름

| 단계 | 담당자 업무 | 확인 자료 | 완료 기준 |
|---|---|---|---|
| 고객 등록·목표 합의 | 고객 측 담당자, 사용자, 도입일, 목표일, 첫 업무를 정함 | 킥오프 메모·고객 합의 | 목표·담당자·기한 합의 |
| 초기 설정 | 계정·부서·문서함·권한 설정 안내 | 관리자 확인·접근 테스트 | 필요한 사용자 로그인·접근 확인 |
| 문서 이관 | 기존 문서·문서함 매핑, 실패 항목 재시도 | 이관 결과·오류 보고서 | 필요한 업무 문서의 이관 확인 |
| 사용자 교육 | 로그인·실습 파일 준비, 게시·검색·버전관리 교육 | 준비 체크리스트·실습 결과 | 주요 사용자가 흐름 직접 실습 |
| 첫 활용 확인 | 실제 업무 문서 게시·다른 사용자 검색을 확인 | 실제 업무 기록·고객 확인 | 합의한 첫 업무 완료 |
| 운영 인계 | 미해결 문의·피드백·지원 창구 정리 | 인계 메모 | 지속 지원 담당자에게 연결 |

설정·이관·교육 중 문의가 생기면: 고객 문의 접수 → 같은 고객의 상태·로그와 제품 문서 대조 → 확인된 사실/원인 후보/질문 구분 → 안내문 검토 또는 기술 담당자 전달 → 작업 등록·결과 확인 → 고객 단계 재점검으로 진행합니다.

현재 앱은 단계 진행률을 자동 갱신하지 않습니다. 샘플 고객은 고정된 완료 단계이며, 새 고객은 확인 전 0%로 시작합니다. 작업 완료와 고객 단계 완료는 별개의 기록입니다.

## ‘게시 전 단계’는 어떻게 아는가?

현재 모노랩은 가상의 문의 ‘저장했는데 동료가 검색할 수 없다’와 샘플 기록 `DOC-104 / DRAFT_SAVED / 현재 상태 DRAFT / 게시 기록 없음`을 제공합니다. 가상 가이드에는 ‘임시 저장 문서는 작성자만 볼 수 있고 게시해야 공유된다’고 정의했습니다. 이 자료를 바탕으로 게시 여부 확인을 먼저 제안합니다.

**현재 기록은 코드에 작성한 샘플이며 실제 서버를 조회한 결과가 아닙니다.** 규칙 기반 모드는 이 시연 사례를 분기하고, 키 설정 후 AI 모드는 전달받은 같은 기록과 문서를 읽습니다. 어느 모드도 실제 문서관리 시스템에 접속하지 않습니다.

실제 연동을 구현한다면 다음 자료를 권한 범위 안에서 조회해야 합니다.

| 자료 | 확인할 내용 | 가능한 출처 |
|---|---|---|
| 문서 현재 상태 | 같은 고객·같은 문서 ID의 DRAFT/PUBLISHED 상태, 수정·게시 시각 | 제품의 문서 상태 API 또는 승인된 읽기 전용 조회 |
| 이벤트 기록 | 저장·게시 성공/실패 이벤트와 기록된 시각 | 제품 활동 로그·정상 수집된 이벤트 |
| 사용자·문서함 권한 | 문서 소유자와 동료의 실제 접근 권한 | 관리자 확인·제품 권한 API |
| 검색 색인 상태 | 게시 이후 색인 성공/실패와 지연 | 검색 처리 로그·상태 API |
| 제품 가이드 | 저장·게시·검색의 동작과 정상 처리 시간 | 해당 제품 버전의 공식 가이드 |

‘게시 이벤트가 안 보인다’만으로 미게시라고 결론 내리면 안 됩니다. 로그 수집 여부·조회 기간·문서 ID·최근 상태를 함께 확인해야 합니다. 현재 상태가 없으면 추가 확인, 서로 다른 최신 상태가 충돌하면 원인 확정 보류로 처리합니다. 제품마다 저장 즉시 공유될 수도 있으므로 이 가상의 ‘게시’ 규칙을 모든 솔루션에 적용할 수는 없습니다.

## 새 고객 추가와 데이터 출처

상단 ‘고객 추가’에서 회사명·업종·담당자·사용 인원·도입일·목표일·첫 활용 목표를 입력합니다. 고객은 현재 브라우저에 저장됩니다. 관련 가이드는 제공되지만 시스템 로그나 문의가 자동으로 생기지는 않습니다.

새 고객 정보와 메모는 담당자 입력 자료입니다. 이를 실제 관찰된 로그로 표현하지 않습니다. 첫 버전에서는 현재 상황을 고객에게 확인하고 메모로 기록할 수 있으며, 자유 입력 해석은 실제 AI 연결 후 가능합니다. 장기적으로는 문의·확인 기록 등록과 제품 API 연동을 별도 기능으로 확장해야 합니다.
