# jihodev 포트폴리오 설명·시연 대본

## 한 문장 소개

고객이 문서관리 서비스를 도입한 뒤 첫 업무를 완료할 때까지, 담당자가 고객 상황을 파악하고 근거에 따른 안내와 후속 작업을 이어가도록 돕는 AI 온보딩 도구입니다.

## 실제 경험과 가상 사례

Linux·Oracle 운영과 기술 문의 대응, PL·PMO 실무의 일정·요청 정리·개발자 협의·테스트·검수 경험을 바탕으로 기획했습니다. 약 300명 대상 사용자 교육, 44장 교육자료와 발표 대본 작성 경험은 교육 준비·사용자 수준에 맞춘 안내 흐름에 반영했습니다.

교육 피드백은 직후 구두 반응과 고객 담당자를 통한 긍정적 피드백입니다. 정량 효과로 표현하지 않습니다. 앱 속 고객·제품 규칙·문의·로그와 분석은 모두 가상이며 실제 고객 성과가 아닙니다.

## 문제 정의

‘저장했는데 검색이 안 된다’는 문의에도 게시 여부, 접근 권한, 색인 상태를 확인해야 합니다. 고객의 말·시스템 기록·제품 가이드를 대조해 안내하거나 기술 담당자에게 전달하고, 이후 실제 활용 여부까지 후속 확인해야 합니다.

## 3분 시연

1. **목표:** 모노랩의 목표는 영업팀 24명이 제안서를 등록·공유·검색하는 것입니다. 단계 진행률과 첫 활용 목표를 따로 보여줍니다.
2. **근거:** 기본 기록의 임시 저장 상태와 게시 기록 부재를 확인합니다. 숫자 인용 버튼으로 원문을 엽니다.
3. **판단 변화:** ‘게시 후 검색 오류’에서는 기술 담당자 전달로 바뀝니다. ‘기록 부족’과 ‘기록 충돌’은 추가 확인을 요청합니다.
4. **설명:** 안내문을 검토·수정합니다. 검증되지 않은 해결 기한을 약속하거나 자동 발송하지 않습니다.
5. **실행:** 작업으로 등록하고 담당자·기한을 정한 뒤 결과 확인 후 완료로 바꿉니다.
6. **정착:** 교육·첫 활용 대기·목표 달성 고객으로 교육 이후 활용과 인계를 설명합니다.

키 연결 전에는 반드시 ‘규칙 기반 데모’라고 설명합니다. 실제 AI는 별도 버튼에서 서버 API를 호출하고 근거 ID와 응답 형식을 검사합니다. 문서 해석 정확성 자체는 이 검사로 보장하지 않습니다.

## 본인의 역할 설명 예시

“제 운영·사업관리·사용자 교육 경험에서 요구사항과 시나리오를 정리했고, AI 코딩 도구의 도움을 받아 구현했습니다. 담당자가 근거를 검토하고 후속 조치를 실행하는 흐름을 설계했습니다. 규칙 기반 시연과 실제 AI 분석을 구분하고, 근거가 부족하면 확인을 요청하도록 구성했습니다.”

실제 수행한 범위에 맞게 수정하고, 모든 코드를 혼자 수작업으로 작성했다고 주장하지 않습니다.

## 평가와 다음 개선

자동 테스트와 브라우저 업무 흐름 검증을 수행했습니다. 실제 고객 사용성 실험·업무 시간 절감은 측정하지 않았습니다. 키 연결 후 원인 판단·문서 해석·질문 적절성·안내문 명확성·지연시간·토큰을 기록합니다. 응답 형식 검사와 업무 판단 평가를 분리합니다.
