# 글쓰기와 사실 기준

## 말투

- 겸손하되 실제로 한 일은 동사로 분명하게 쓴다. "참여했습니다"로 뭉개지 말고 무엇을 작성·정리·확인·수정했는지 쓴다.
- 과장된 전문가 페르소나, 딱딱한 기술 매뉴얼, 거창한 추상어("혁신", "패러다임", "시너지", "극대화", "최고의")는 쓰지 않는다.
- 소제목은 문장형으로 자연스럽게, 그 문단에서 실제로 한 일을 담는다. ("~을 직접 만들었습니다", "~을 보고 고쳤습니다")
- 합격을 보장하는 말 대신 읽는 사람이 역할·기여·검증을 판단할 수 있게 쓴다.
- 경력 방향(국비과정 때 느낀 강점 → 먼저 엔지니어로 입사 → 학위·자격 병행)은 필요할 때 한두 문장으로만 쓰고 자기비하로 쓰지 않는다.
- 공고에서 묻지 않으면 퇴사 사유·공백기를 일반 자소서에 쓰지 않는다. 공백기에 했다는 일을 새로 만들지 않는다.

## 분량

- 문항·글자 수 제한이 있으면 그것이 우선이다. 공백 포함/제외 기준을 공고에서 확인하고, 모르면 둘 다 보고한다.
- 제한이 없으면 기본본 정도(공백 포함 약 2,000~3,000자)를 쓴다.
- 보통 소제목 4~5개, 소제목마다 한 문단(4~7문장).

## 기본본을 다루는 방식

1. 흐름은 기본본을 유지한다. 공고에 맞춰 순서를 바꾸고, 문장을 보강하고, 공고 업무와 연결하는 문장을 더한다.
2. 해커톤(한끗)은 기존 경력에 **더하는 경험**이다. 첫 소제목이나 글 전체의 주인공으로 만들지 않는다. 한 소제목 이내.
3. AX 흐름: 반복 업무 문제의식 → 실무 경력 → 직접 만든 도구와 검증 → (해커톤) → 입사 후 할 일.
4. 온보딩·기술지원 흐름: 사용자 교육 → 질문을 개발자와 연결 → 기술지원 기초 → (해커톤 사용자 행동 개선) → 개인 프로젝트와 입사 후 할 일.
5. 공고가 둘 다에 걸치거나 사용자가 둘 다 요청하면 두 패킷을 따로 만든다.

## 사실 기준 (가장 중요)

- 모든 문단은 `references/profile.json`의 fact ID를 근거로 가진다. 근거 없는 사건·수치·기관명은 쓰지 않는다.
- 사용자 문답(conversation), 이력서(resume), 저장소 구현(personal/hackathon), 추정, 앞으로의 계획을 구분한다. 계획은 "~하겠습니다"로만 쓴다.
- 과거에 "그럴싸하게 꾸며 달라"고 한 요청이 있었더라도 그것은 사건이 실제 있었다는 근거가 아니다.
- 웹에서 찾은 다른 기관 사례는 참고 아이디어일 뿐 지원자가 벤치마킹했다는 증거가 아니다.
- 저장소에 있는 기술 = 지원자가 모두 수작업 코딩했거나 상용 운영했다는 뜻이 아니다. 개인 프로젝트는 "AI를 활용해 기획·설계·구현·검증을 혼자 진행"으로 쓴다.
- 실무 경력 / 개인 학습 프로젝트 / 팀 프로젝트 / 가상 시연을 섞지 않는다.

### 숫자는 맥락과 붙여 쓴다

| 숫자 | 반드시 함께 쓸 맥락 | 쓰면 안 되는 해석 |
|---|---|---|
| 약 300명 | 대면 교육·기능 시연 대상 | 활성 사용자, 고객 수, 만족 인원 |
| 44장 | 교육자료(슬라이드) 장수 | 교육 횟수 |
| 13개 | 에이전트가 고를 수 있는 도구 수 | 기능 13개 상용 출시 |
| 172건 | 한끗 팀의 계산 엔진 기대값 시험 | 본인이 혼자 작성, 일반 정확도 |
| 8건 | 가상 공고 AI 추출 시험 | 정확도 100% |

### 쓰지 않는 주장 (확인되지 않음)

- Claude Team 관리자 운영, MCP 서버 직접 제작, 서브에이전트 운영, 반도체 장비 제어, 상용 운영 AI 성과
- 업무 시간 절감·문의 감소·만족도 같은 측정되지 않은 성과 수치
- 공식 PM·PL 총괄, 서비스 전체 단독 개발, DBA 전문성, 클라우드 인프라 구축
- 해커톤 수상·순위, 한끗의 법률·금융 정확성 보증
- Microsoft Clarity 원본 대시보드·세션 영상을 이번에 읽었다는 주장 (관찰 내용은 사용자 답변이 근거)
- Git 터미널 숙련도, 해외 출장 가능, 타 지역 근무 가능, 입사 가능일, 영어 독해 수준, AX 과정 수료월

공고가 이런 항목을 필수로 요구하면 지어내지 말고 `공고분석.md`의 "부족·미확인"에 넣고, 사용자에게 한 번에 묶어서 묻는다. 자소서에는 확인된 범위로만 쓰거나, 아직 경험이 없다는 것을 짧게 밝히고 배울 방법을 쓴다.

## 이력서 제목

- 30~45자 내외, "~하고 싶은 김지호입니다" 같은 겸손한 형태.
- 회사·직무 핵심어 1개와 실제 강점 1개를 담는다. "최고", "전문가", "인재" 같은 자기 평가는 피한다.
