# 채용 담당자 관점 검토 (공격적 검토)

초안을 쓴 뒤 IT기업 채용 담당자가 서류를 30초 안에 거른다고 가정하고 아래 질문으로 문장마다 공격한다. 찾은 문제와 고친 내용은 brief의 `review` 배열에 `{"issue": ..., "fix": ...}`로 남기고, 실제로 본문을 고친다. 고친 뒤 한 번 더 같은 질문으로 읽는다.

## 1. 30초 훑기

- 소제목만 읽어도 "무슨 일을 했고, 이 공고의 어떤 업무와 이어지는지" 보이는가?
- 첫 소제목이 공고 핵심 업무와 연결되는가? 해커톤이 주인공이 되지 않았는가?
- 이력서 제목만 보고 이 직무에 맞는 근거(맥락 있는 숫자·직접 만든 결과물)가 보이는가? 희망만 말하는 제목이 아닌가?

## 2. 약한 문장 찾기

| 약한 신호 | 고치는 방법 |
|---|---|
| "참여했습니다", "경험이 있습니다"로 끝남 | 무엇을 작성·확인·전달·수정했는지 동사로 |
| "열정", "성실", "최선", "역량을 키웠습니다" | 그걸 보여 준 행동 한 가지로 바꾸거나 삭제 |
| 공고 문구를 그대로 반복 | 그 업무에 내가 한 일 한 가지를 붙임 |
| 도구 이름 나열 | 그 도구로 무엇을 판단·검증했는지 |
| 결과만 있고 검증이 없음 | 어떻게 확인했는지, 무엇을 고쳤는지 |
| 입사 후 포부가 추상적 | 첫 몇 달에 할 구체 행동(업무 흐름 듣기, 작은 자동화, 가이드 작성 등) |

## 3. 의심하는 질문 (면접관이 물을 것)

- "이건 혼자 한 건가요, 팀이 한 건가요?" → 문장에 역할이 드러나는가?
- "실제 고객/사용자가 쓴 건가요?" → 가상 데이터·시연이면 같은 문단에 밝혔는가?
- "숫자 300명은 무엇의 수인가요?" → 숫자 바로 옆에 맥락이 있는가?
- "AI가 짠 코드를 본인이 이해하나요?" → 무엇을 확인하고 고쳤는지 구체 사례가 있는가?
- "공고 필수 요건 X는요?" → 확인되지 않은 요건을 있다고 쓰지 않았는가? 필요한 곳에만 짧게 솔직히 썼는가?

## 4. 사실 검사

- 문단마다 profile fact ID가 붙어 있는가? (`scripts/career_packet.py check`가 검사)
- `writing-guide.md`의 "쓰지 않는 주장"이 들어가지 않았는가?
- 공백 포함/제외 글자 수가 기준 안인가?

## 5. 포트폴리오 화면 검토

- 첫 화면에 회사·직무와 지원자가 할 수 있는 일이 한 문장으로 보이는가?
- 프로젝트마다 개인/팀, 본인 역할, 가상 데이터·시연 한계가 카드 안에 보이는가?
- 눌리지 않는 요소가 버튼처럼 보이지 않는가? 모션이 업무 흐름 이해에 쓰이는가?
- 내부 근거·미확인 자격·퇴사·공백 정보가 제출용 화면에 섞이지 않았는가?
