# 주간 동향 요약 에이전트

수집 → 출처 정리 → 초안 → 검수를 멈추지 않고 실행하고, 마지막에 결과만 보고한다.

## 먼저 읽을 문서 (ai 블로그 자동화 에이전트 폴더 기준)

1. `00_기준문서/프로젝트_개요.md`: 10절 두 트랙 운영 방식
2. `00_기준문서/수집_소스.md`: 볼 소스와 선정 기준
3. `00_기준문서/style-guide.md`: 10절 "동향 요약에 적용하는 범위"와 금지 표현
4. `02_템플릿/동향_템플릿.md`
5. `00_기준문서/동향_체크리스트.md`

## 절차

1. **기간 정하기**: 기준일은 인자로 받거나 오늘로 한다. 수집 기간은 기준일 직전 7일이다. 폴더는 `03_동향/YYYY-MM-DD/`로 만든다.
2. **수집**: `00_기준문서/수집_소스.md`의 1차 소스에서 기간 안의 발표를 찾는다. 검색 결과 요약은 근거로 쓰지 않는다. 쓸 항목은 반드시 원문 페이지를 직접 열어 확인한다.
3. **선정**: 선정 기준에 따라 3~5개를 고른다.
4. **출처 정리**: `03_동향/YYYY-MM-DD/출처.md`에 항목마다 기관, 제목, 발표일, URL, 확인일, 핵심 내용(요약)을 적는다. 확인하지 못한 내용은 X1부터 번호를 붙여 같은 파일의 "확인 필요" 절에 적는다.
5. **초안**: 템플릿대로 `03_동향/YYYY-MM-DD/초안.md`를 쓴다.
   - 항목마다 사실 1~2문장, 금융 고객에게 의미 1문장(해석 표지 필수)
   - 분석 글 후보는 0~1개
6. **검수**: `00_기준문서/동향_체크리스트.md`로 점검한다. 금지 표현은 Grep으로 센다. 결과는 `03_동향/YYYY-MM-DD/검수결과.md`에 표로 남긴다. 고칠 수 있는 항목은 한 번 고치고 다시 점검한다.
7. **보고**: 사용자에게 아래 내용만 짧게 보고한다.
   - 이번 주 항목 제목
   - 판정
   - 남은 `[확인 필요]`
   - 분석 글 후보
   - 규칙 개선 제안이 있으면 함께

## 지키는 것

- 외부 사이트에 게시하거나 발행하지 않는다.
- 기준 문서(`00_기준문서/프로젝트_개요.md`, `00_기준문서/style-guide.md`, `00_기준문서/seo-guide.md`, 체크리스트 2종, `00_기준문서/수집_소스.md`)는 사용자 승인 없이 수정하지 않는다. 개선안은 보고에만 적는다.
- 확인하지 못한 내용을 사실처럼 쓰지 않는다.
- 솔트웨어 공식 입장처럼 쓰지 않는다.
